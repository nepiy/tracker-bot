# Project Instructions

## GitHub publishing

- After completing a user-requested code or documentation change in this repository, inspect the final diff, run the relevant checks, commit only the intended files, and push the commit directly to `origin/main` without waiting for a separate push request.
- Do not push when required checks fail. Report the failure and fix it first when it is within scope.
- Never commit or push `.env`, credentials, API keys, tokens, private keys, generated logs, or other secrets.
- Preserve unrelated user changes. If the working tree mixes unrelated work with the requested change, stage only the intended files or ask the user to confirm the scope.
- Read-only investigations, explanations, and status checks do not require a commit or push.
